# AGENTS.md

This file is the source of truth for coding-agent guidance in this repository. Keep
agent-agnostic project instructions here, and keep tool-specific files as thin adapters.
`CLAUDE.md` is intentionally a symlink to this file so Claude and Codex read the same
repository policy.

## Overview

reactive-home is an experiment combining home automation with modern FRP. It is a Cabal
monorepo (`packages: */*.cabal`) with several package families:

- **`hasquitto-*`** — a from-scratch, low-level **MQTT v5 client** library plus reconnect
  and integration helpers.
- **`haskesame-*` / `simpleble-hs/`** — a Sesame 5 BLE client, BLE transports, and MQTT
  bridge executables.
- **`reactive-home/`** — the FRP home-automation layer (built on **Rhine**, bridged into
  the **Effectful** monad), consuming MQTT via hasquitto-core. Early-stage scaffolding —
  `reactive-home/app/Main.hs` is currently a stub.

Read `ARCHITECTURE.md` first for the repository map, then the relevant family document
under `ARCHITECTURES/` before making design changes. You can grasp the current
architecture from those files, and you must update them after design changes.

## Build / test / run

Cabal nix-style builds; `cabal.project` is the source of truth. GHC **9.12.4**, pinned via
`cabal.project.freeze` and `ci/configs/`. Do not use stack or invoke `ghc` directly.

```bash
cabal build all                # build every package
cabal build hasquitto-core     # build one package
cabal test all                 # run all test suites
cabal repl hasquitto-core      # REPL for a package
```

Prefer HLS (via the haskell skill) for iterating. Do not pass `-fno-code` via
`--ghc-options`; it does not speed up Cabal builds here and can confuse the compiler.

### Tests — tasty + tasty-discover (property tests via `falsify`)

Suites: `hasquitto-core-test` (unit/property, auto-discovered), `hasquitto-core-integration`
(needs a live broker), `reactive-home-test`.

- Test suites use `tasty` + `tasty-discover` with `--tree-display`. Keep `test/Test.hs`
  as the generated driver only, and put tests in hierarchical modules mirroring source
  modules, named like `Hoge.Fuga.FooTest`.

```bash
cabal test hasquitto-core-test
cabal test hasquitto-core-test --test-options '-p Codec'   # filter to a module/pattern (tasty -p)
```

The integration suite needs an MQTT broker (CI uses `eclipse-mosquitto:2.0.18` on
`localhost:1883`). Endpoint is configurable via `--mqtt-host`/`--mqtt-port` or the
`TASTY_MQTT_HOST`/`TASTY_MQTT_PORT` env vars:

```bash
cabal test hasquitto-core-integration --test-options '--mqtt-host localhost --mqtt-port 1883'
```

## Conventions & workflow

- Prefer `(<>)` over `(++)` for all concatenation (lists and strings included).
- **Formatting is enforced** by CI and by shared PostToolUse hooks in `.agents/hooks/`
  wired from Claude/Codex configuration:
  - `.hs`/`.lhs`/`.hsig` -> fourmolu (config: `fourmolu.yaml`); use the Haskell formatter
    integration available in your agent.
  - `.cabal`/`cabal.project*` -> cabal-gild; use the cabal-gild integration available in
    your agent.
- There is **no `package.yaml`/hpack** — edit `.cabal` files directly, then run cabal-gild.
- `.cabal` module lists are generated by cabal-gild `discover` directives. After
  adding/removing/renaming a module, re-run cabal-gild instead of hand-editing the list.
  Modules matching `**/Internal.hs` or `**/Internal/**` become hidden `other-modules`;
  everything else is exposed.
- Strict warnings (see `common defaults` in each `.cabal`): `-Wall -Wcompat
  -Wunused-packages …`. `-Wunused-packages` means a now-unused `build-depends` entry breaks
  the build — drop deps you stop using.
- CI (`.github/workflows/haskell.yml`): build, all test suites, `fourmolu --check`, and a
  cabal validation (`ci/scripts/cabal-check-packages.sh`).
- Commit must follow Conventional Commits (https://www.conventionalcommits.org) style and you must make the coauthorship clear by appending `Co-authored-by` trailer. Also, include a brief summary of changes in the message body.

## Architecture

Read `ARCHITECTURE.md` for the repository-level package map. Family-level design documents
live under `ARCHITECTURES/`; update the relevant document in the same change when altering
package boundaries, concurrency models, protocol recovery, retry semantics, topic/payload
contracts, or public configuration surfaces.

### hasquitto-core
Read `hasquitto-core/ARCHITECTURE.md` before touching the codec or client engine. In brief:
four layers, each importing only from those above it —
**(a)** pure vocabulary `Network.Mqtt.Types.*`,
**(b)** pure wire codec `Network.Mqtt.Codec`,
**(c)** IO transport `Network.Mqtt.Connection` / `.TCP` (pluggable byte transport + packet
framing), and
**(d)** IO client `Network.Mqtt.Client` (concurrent engine) plus `Message` / `Exception`.
`*.Internal` modules hold the implementation; public modules are curated re-exports. Record
style is `NoFieldSelectors` + `OverloadedRecordDot` + `DuplicateRecordFields`, with `mk*`
smart constructors for validated types and `default*` option records you override.

Entry points: `connect`, `publish`, `subscribe`/`subscribe1`,
`recvMessage`/`recvMessageSTM` (pull-based, not callbacks). Pure codec: `encodePacketBS` /
`decodeFrame`. Topics: `mkTopic`, `mkTopicFilter`, `matches`.

### reactive-home
`Home.Reactive` re-exports Rhine plus orphan instances. `Home.Reactive.Orphans` provides
the `MonadSchedule (Eff es)` instance that lets Rhine clocks run in the Effectful monad.
`Home.Reactive.MQTT` holds `MQTTSettings` (JSON-configurable) and the MQTT↔FRP bridge. The
intended direction is to layer device models / automations as Rhine networks sourced from
hasquitto-core.
